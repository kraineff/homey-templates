# Шаблоны конвертации Homey → Яндекс

Шаблон описывает, как умение устройства Homey превращается в умение или свойство
Yandex Smart Home. Этот скилл лежит в самом репозитории шаблонов и обслуживает двоих:
человека, который пишет шаблон руками, и автогенерацию в стеке `api` — она читает те же
правила отсюда, чтобы источник правды был один.

**Синтаксис SDK описан в `README.md` репозитория** — фабрики, поля конфига, пресеты,
`substitute`, типобезопасность. Здесь другое: как по реальному устройству принять
решение, что и во что отображать, и как это проверить.

## Процедура

### 1. Посмотреть на живое устройство

Догадываться о составе умений не нужно — есть хаб. Скрипт лежит в стеке `api` (он
читает его секреты и базу, поэтому в этом репозитории ему не место) и токены никуда
не печатает.

```bash
cd ~/server/apps/api/app/tools

bun inspect.ts --list                              # какие хабы привязаны
bun inspect.ts --homey <id>                        # все устройства хаба
bun inspect.ts --homey <id> --device батарея       # одно устройство
bun inspect.ts --homey <id> --gaps                 # только умения без шаблона
bun inspect.ts --homey <id> --scaffold dim         # заготовка шаблона
```

Вывод по устройству — это ровно те исходные данные, которые нужны для решения:

```
"Левая батарея"  [Спальня]  класс thermostat  иконка heating
    driverId: homey:app:com.xiaomi-mi:airrtc.agl001  (шаблон есть)
    тип Яндекса: devices.types.thermostat
    умения:   range/temperature, toggle/controls_locked, on_off/, mode/thermostat
    свойства: float/battery_level, float/temperature, event/open
      target_temperature       = 15   (number "°C" min 5 max 30 w)
    ~ alarm_thermostat         = true   (boolean r)
```

`w` — записываемое, `r` — только чтение. Знак `!` слева — умение ни во что не
превращается, `~` — не превращается, но у устройства есть шаблон драйвера, который
мог обслуживать его на запись (проверь шаблон глазами).

Покрытие считается **фактически**: умение убирается у копии устройства и сравнивается
результат конвертации. Поэтому умение, которое обслуживает шаблон драйвера, а не
одноимённый файл, пробелом не считается.

### 2. Решить: умение или свойство

У Яндекса это разные сущности, и перепутать их нельзя:

- **Умения** (`capabilities`) — то, чем можно управлять: `on_off`, `range`, `mode`,
  `toggle`, `color_setting`, `video_stream`.
- **Свойства** (`properties`) — только показания: `float` (число) и `event` (событие).

Ориентир — `setable` у умения Homey. Записываемое почти всегда умение, только
чтение — свойство. Исключения бывают: кнопка (`button.*`) записываемая, но у Яндекса
это `on_off` с `momentary`.

### 3. Выбрать билдер

| Умение Homey | Признак | Билдер |
| --- | --- | --- |
| `boolean`, записываемое, главное вкл/выкл | `onoff` и аналоги | `sdk.state` |
| `boolean`, записываемое, побочная функция | подсветка, блокировка, пауза | `sdk.toggle` |
| `boolean`, записываемое, кнопка без чтения | `button.*` | `sdk.state({ momentary: true })` |
| `boolean`, только чтение, тревога | `alarm_*` | `sdk.event` |
| `number`, записываемое, доля `0..1` или `0..100` | `dim`, `volume_set`, `windowcoverings_set` | `sdk.percent` |
| `number`, записываемое, свой диапазон | `target_temperature` | `sdk.range` + `parse` |
| `number`, только чтение, единица фиксирована | `measure_battery` | `sdk.float` |
| `number`, только чтение, единица плавает | `measure_pressure` | `sdk.floatUnit` |
| `enum`, записываемое | режим работы | `sdk.mode` |
| цвет / температура света | `light_hue`, `light_temperature` | `sdk.color` |

### 4. Выбрать instance и единицу

Каждый билдер принимает только свои `instance` — неверный не скомпилируется. Полные
списки, единицы, допустимые события и режимы — в `reference/mapping.md`.

### 5. Написать и проверить

Файл кладётся в `system/` (системное умение Homey), `custom/` (умение отдельного
приложения) или `devices/` (по `driverId`). **Имя файла без расширения — это ключ**,
папка ни на что не влияет.

```bash
bunx tsc --noEmit          # в корне репозитория шаблонов
```

Битый шаблон не роняет сервис — он пропускается с записью в лог, а устройство
остаётся без поддержки. Поэтому проверять обязательно локально.

`apps/api/app/templates` на сервере — **настоящий чекаут** репозитория шаблонов,
смонтированный в контейнер `:ro`. Правь файлы прямо там: приложение следит за папкой
и перезагружает реестр за считаные секунды, без коммита и пересборки. Проверяй
результат тем же `inspect.ts` — он читает ту же папку.

Когда шаблон готов — коммит и пуш из этой же папки. Свежесть чекаута держит сайдкар
`api_templates` (`fetch` + `merge --ff-only` раз в 5 минут); незакоммиченные правки он
не затирает, а приостанавливает обновление с записью в лог.

## Грабли

**Единицы локализованы.** Homey отдаёт подпись единицы на языке хаба: на русском
хабе придёт `мбар`, а не `mbar`. В `convert` у `floatUnit` держи ключи и на латинице,
и на кириллице.

**Доли, а не проценты.** `dim` в Homey — это `0..1`, а Яндекс ждёт `0..100`.
`sdk.percent` разбирается сам, включая `capabilitiesOptions` устройства; вручную
масштабировать не нужно.

**У события — закрытый набор значений.** Для `motion` допустимы только `detected` и
`not_detected`, для `water_leak` — `dry`/`leak`, и так далее. Значение вне набора
Яндекс отвергнет. Списки — в `reference/mapping.md`.

**Одно плохое значение роняет весь ответ.** Яндекс отбраковывает пачку целиком на
первом невалидном поле, поэтому движок отсеивает `null`/`NaN`/бесконечности, поджимает
проценты к `0..100` и отбрасывает события вне набора. Не полагайся на это: возвращай
`undefined` из `get`, если значения нет.

**Суффиксные умения.** `measure_power.total` обслуживается шаблоном базового
`measure_power` — отдельный файл под суффикс не нужен. Работает только для
`measure_*`, `meter_*`, `alarm_*`.

**Приблизительные соответствия — через `substitute`.** У Яндекса нет отдельного CO,
поэтому `alarm_co` отображается в `event gas` с `substitute: true`: при наличии
настоящего `alarm_gas` подменное отбрасывается. Пары перечислены в README репозитория.

**Заметки устройства сильнее шаблона.** `@hidden;` в заметке убирает устройство из
выгрузки целиком, `@type=light.garland;` жёстко задаёт тип. Если устройство «пропало»
у Яндекса — сначала проверь заметку, а не шаблон.

**Тип устройства.** Определяется по классу и иконке Homey автоматически. Задавать
`deviceType` в шаблоне нужно, только если автоопределение ошибается: это уместно в
`devices/` (шаблон конкретного драйвера), а не в шаблоне отдельного умения.

## Где что лежит

- Этот репозиторий — `kraineff/homey-templates`; рабочий чекаут на сервере:
  `~/server/apps/api/app/templates` (в git сервера не входит, поддерживается
  сайдкаром `api_templates`). Скилл вызывается на сервере как `/homey-templates`
  через симлинк на папку `skill/` этого чекаута.
- `templates/sdk.ts` — типы для шаблонов, **генерируется** движком прямо в чекаут:
  `cd ~/server/apps/api/app && bun run gen`. Руками не править; после генерации
  коммитить в репозиторий шаблонов.
- Движок конвертации — `~/server/apps/api/app/src/alice/converter/`.
- Перечисления Яндекса (типы, instance, единицы, режимы, события) —
  `~/server/apps/api/app/src/alice/models/yandex.ts`. Новый instance или единица
  сначала добавляется туда, потом `bun run gen`, и только потом доступен шаблонам.
