# homey-templates

Шаблоны конвертации устройств Homey в формат Yandex Smart Home. Их читает мост
Алисы (стек `api` домашнего сервера) и применяет **без перезапуска**: на сервере
этот репозиторий развёрнут рабочим чекаутом, за папкой следит вотчер, и
сохранённый файл доезжает до Яндекса за секунды.

## Главное, что нужно помнить

**Шаблон действует на всех пользователей моста, а не на автора.** Ключ — это id
умения Homey (`measure_power`) или `driverId` модели, и он общий. Поэтому:

- заполнять пробел (умение, которое сейчас ни во что не превращается) безопасно:
  хуже, чем «не поддерживается», не станет;
- **менять существующий шаблон рискованно** — ошибка масштаба или единицы
  разъедется по всем сразу и выглядит правдоподобно;
- движок поджимает проценты к `0..100`, поэтому неверный множитель не отбраковывается,
  а маскируется под стабильные «100%». Проверяйте значение на живом устройстве, а не
  только компиляцию.

## Как писать шаблон

Процедура, таблицы соответствий и грабли — в скилле `.claude/skills/create`
(в Claude Code вызывается как `/create`). Синтаксис SDK — в `README.md`.

Коротко: умение Homey → решить, умение это Яндекса или свойство → выбрать билдер →
выбрать `instance` и единицу → проверить.

## Структура

```
system/    системные умения Homey      (measure_power, dim, onoff, …)
custom/    умения сторонних приложений (child_lock, nh_measure_*, …)
devices/   шаблоны моделей по driverId (com.sensibo:Sensibo, …)
sdk.ts     типы и фабрики — ГЕНЕРИРУЕТСЯ движком, руками не править
```

Имя файла без расширения — это ключ; папка на него не влияет, только раскладывает.

## Проверка перед коммитом

```bash
bunx tsc --noEmit
```

Битый шаблон не роняет мост: он пропускается с записью в лог, а устройство остаётся
без поддержки. Поэтому проверять обязательно локально — молчаливая потеря устройства
хуже явной ошибки.

Если рядом развёрнут сервер, результат на живых устройствах показывает
`~/server/apps/api/app/tools/inspect.ts` (`--gaps` — умения без шаблона).

## `sdk.ts`

Генерируется из перечислений движка. Новый `instance`, единица или тип устройства
сначала добавляются в `api/app/src/alice/models/yandex.ts`, затем
`cd ~/server/apps/api/app && bun run gen`, и только после этого доступны шаблонам.

## Автогенерация

Мост сам находит умения без шаблонов на подключённых хабах и просит Claude написать
шаблон по этим же правилам — скилл отсюда и есть источник правды для обеих дорог,
ручной и автоматической. Сгенерированное проходит те же проверки плюс регрессию
(шаблон обязан только добавлять) и попадает сюда коммитом. Если соответствия у
Яндекса нет — шаблон не создаётся, а причина пишется в комментарии.
